# Change Log

Every change to requirements, design or behaviour is recorded here, newest first.
Format: **date · ID · what changed · why · documents/code updated**.

| Date | ID | Change | Why | Updated |
|---|---|---|---|---|
| 2026-11-22 | C-010 | **Joining and removing work in bigger groups.** A join approval now carries the signed group record once (not twice) and is compressed before sealing. Approving again after the connection dropped re-sends the approval instead of failing with "invite already used". Removing someone sends the new key in as many messages as needed, each with the group record and a share of the members' sealed keys. The test relay now refuses messages over ntfy.sh's size limit, like the real one. An invite that isn't accepted logs why. | Found in the two-phone test: Ravi's approval of Asha was over ntfy.sh's ~3.8 KB message limit, so it was never sent, and approving again was refused. A new 7-member test showed key rotation had the same problem. | Core.Sync (FamilySync.Membership, Wire), Core.Families (InviteCodec), App JoinViewModel, test relay, 2 new tests, TD-01 |
| 2026-11-22 | C-009 | Moving to a month that hasn't started no longer shows an empty "Bills" heading | Found in the emulator test | App MonthViewModel |
| 2026-11-22 | C-008 | **Receipt reading:** a number printed with paise ("33.00") is never taken as a quantity, so when OCR misses the quantity, the row is read as rate × amount. The shop name is the first row about as big as the biggest one above the products, not simply the tallest: letters like g and y made the address row's box taller than the shop name in capitals. | Found with a test receipt on the emulator: "Milk 1L 2 33.00 66.00" was read as 33 × 2.00, and the shop as "MG Road Bengaluru" instead of "Fresh Mart Supermarket" | Core.Receipts (ReceiptParser), 1 new test, TD-03 |
| 2026-11-22 | C-007 | **Replay protection is a sliding window** (each sender's message number is accepted once, in any order, within the last 256) instead of "must be higher than the last". After a live message, the app waits a second before fetching, and tries once more if the fetch finds nothing. | Found in the two-phone test with the real ntfy.sh: a confirmed bill and the month's new status were sent in the same second, ntfy.sh returned them in the other order, and the bill was thrown away as a replay. ntfy.sh also announces a message slightly before a fetch returns it. | Core.Sync (FamilySync, SyncState), App SyncScheduler, 1 new test, TD-01 |
| 2026-11-22 | C-006 | **Live sync on Android uses its own streaming HTTP client** (`SocketsHttpHandler`, no overall timeout), and the stream reconnects if nothing (not even a keepalive) arrives for 100 s. Sync results and problems are written to the Android log (`FamilyLists` tag). The Group screen refreshes "Synced … ago" after every sync. An empty to-do list says "Empty", not "All done". | Found in the two-phone test: ticks from the other phone took 19–31 s (the one-minute timer), although the same stream code delivered within a second on a PC | Core.Relay (NtfyRelay.WatchAsync), App SyncScheduler, AppServices, GroupPage, ListsViewModel, TD-01 |
| 2026-11-22 | C-005 | Each change used to wait 1.5 s before the screen updated. It now updates at once; sending happens in the background. | Found in the emulator test: quick-adding six items felt slow | App VaultHost |
| 2026-11-22 | C-004 | The item and draft-bill screens load once, so a sync from another phone can't overwrite what is being typed | Found in the emulator test | App ItemViewModel, BillViewModel |
| 2026-11-21 | C-003 | **Optional Claude bill reader**, using the official Anthropic C# SDK (Apache-2.0), model `claude-opus-5-5` with a JSON-schema answer. Off by default; the person's own API key is stored encrypted on that phone only. | The user's choice: on-phone reading first, Claude as an option | Core.ClaudeReader, App Settings, TD-03 |
| 2026-11-21 | C-002 | **Months and carried items get derived ids** (SHA-256 of list + period + name), and a seed version that any real edit beats | Two phones starting the same month offline must end up with one month, not two | Core.Common (Ids.Derive), Core.Lists, TD-02 |
| 2026-11-21 | C-001 | **Rebuilt as a serverless Android app** (.NET 10 MAUI, encrypted SQLite, ntfy.sh sync), replacing the React + Supabase web app, which is kept on the `web-supabase` branch. The repository becomes public so the in-app updater can read releases. | The user wanted no accounts, no cost and an installable APK, on the same stack as Travel Vault and Use It Before | Whole repository, README, TD-01 to TD-04 |
